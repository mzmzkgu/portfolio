# `/history` 엔드포인트 연동 가이드 (서버 저장소용)

이 문서는 `mzmzkgu/portfolio` 프론트엔드(`index.html`)가 새로 기대하게 된 시세 히스토리
API를, 시세 서버(백엔드, `kgu3405.duckdns.org` / `API_BASE`)를 담당하는 별도 저장소에서
그대로 구현할 수 있도록 필요한 계약(contract)을 정리한 문서다.

## 배경

포트폴리오 앱 자산 탭에 종목별 "1년 일봉 스파크라인 차트"를 추가했다
(브랜치 `claude/add-yearly-chart-to-status-1ndt7t`, 커밋 `f62a834`).

- **코인**(sector `가상자산`)은 프론트에서 업비트 공개 캔들 API
  (`https://api.upbit.com/v1/candles/days`)를 직접 호출한다. 서버가 손댈 부분 없음.
- **주식**(미국/한국)은 프론트가 `${API_BASE}/history`를 호출하도록 이미 코드가 들어가
  있는데, 이 엔드포인트가 서버에는 아직 없다. 이 문서에서 그 계약을 구현해달라는 것.

## 엔드포인트 계약

```
GET {API_BASE}/history?ticker=<TICKER>&days=365
```

- `ticker` (필수): 프론트가 보유 종목에 등록한 티커 문자열 그대로.
  - 미국 주식: `AAPL` 같은 일반 티커.
  - 한국 주식(KRX): 기존 `/prices`, `/watchlist/*`에서 쓰는 것과 같은 6자리 코드
    (예: `005930`). 서버가 이미 `getTickerType()` 판별 로직과 동일한 포맷으로
    KIS API를 호출 중이므로, 그 매핑을 그대로 재사용하면 됨.
  - 코인 티커(`KRW-BTC` 등)는 이 엔드포인트로 들어오지 않는다 (프론트가 걸러서 안 보냄).
- `days` (선택, 기본 365): 최근 며칠치를 줄지. 지금 프론트는 항상 `365`로 보냄.

### 응답 형식

```json
{
  "ticker": "AAPL",
  "prices": [
    { "date": "2024-09-30", "close": 226.21 },
    { "date": "2024-10-01", "close": 227.55 },
    ...
    { "date": "2025-09-29", "close": 254.43 }
  ]
}
```

- `prices`는 **과거 → 최근 순으로 정렬**(ascending)되어야 한다. 프론트는 배열을
  그대로 순서대로 그려서 스파크라인을 만든다.
- 각 원소는 `{date, close}` 객체가 기본이지만, 프론트 파싱 코드
  (`fetchStockHistory`, index.html)는 아래도 허용하므로 꼭 이 형태를 맞출 필요는 없음:
  - 최상위 키가 `prices` 대신 `closes`나 `data`여도 인식함.
  - 배열 원소가 그냥 숫자(`[226.21, 227.55, ...]`)여도 되고,
    객체면 `close`, `c`, `price` 중 아무 키나 있으면 됨.
  - 즉 최소 계약은 "숫자 종가 배열을 과거→최근 순으로 주는 JSON"이고,
    위 예시 형식이 가장 명확하니 그대로 맞춰주는 걸 추천.

### 실패/데이터 없음 처리

- 프론트는 이 호출을 `try/catch`로 감싸고, 실패하거나 배열 길이가 1 이하면 그냥
  "차트 없음"을 보여주고 넘어간다. 즉 **500을 던지지 말고**, 데이터가 없으면
  `200` + `{"ticker": "...", "prices": []}` 형태로 응답하는 걸 권장 (그래도 무해하긴 함).
- 신규 등록 직후처럼 아직 캐시가 없는 티커는 빈 배열을 내려주고, 백그라운드로
  채운 뒤 다음 요청부터 채워서 주는 방식이 기존 `/watchlist/sync` 패턴과 잘 맞음.

## 데이터 소스 제안

- 이미 `/prices` 응답에서 `source`가 `finnhub` / `yahoo` / `kis_*` / `upbit` 등으로
  오는 걸 보면, 서버가 KIS(한국투자증권) API 인증을 이미 들고 있을 가능성이 큼.
  - 국내주식: KIS "국내주식기간별시세(일/주/월/년)" API 재사용.
  - 해외주식: KIS "해외주식 기간별시세" API, 혹은 기존에 쓰던 Finnhub/Yahoo 소스로
    일봉 종가만 뽑아도 무방. 프론트는 소스를 구분하지 않는다.

## 캐싱 권장

- 일봉 종가는 장 마감 전까지는 하루 한 번만 바뀌므로, 서버에서 티커별로
  최소 몇 시간 ~ 하루 단위 캐시를 두는 걸 권장 (기존 watchlist 캐싱 구조 재사용).
- 프론트도 세션(탭 열려있는 동안)당 티커당 1회만 요청하도록 이미
  `histCache` 메모리 캐시가 들어가 있어서, 렌더링될 때마다 매번 다시 부르지 않음.

## CORS

- 기존 `/prices`, `/watchlist/add`, `/watchlist/touch`, `/watchlist/sync`, `/name`과
  동일한 CORS 정책을 그대로 적용하면 됨 (브라우저에서 직접 fetch).

## 참고: 프론트 쪽 관련 코드 (mzmzkgu/portfolio, index.html)

- `fetchStockHistory(ticker)` — `/history` 호출 및 응답 파싱
- `fetchUpbitHistory(market)` — 코인용 (서버 무관)
- `ensureHistory(ticker, sector)` / `histCache` — 캐싱
- `svgSparkline(closes, avgCost)` — 렌더링 (평단가 기준선 위/아래 색 전환)
- 위치: 자산 탭 종목 리스트 렌더 함수 `rHold()` 안에서 호출됨

구현 후 확인 방법: 프론트에서 아무 미국/한국 주식 종목이나 자산 탭에서 열어보고
카드 오른쪽에 스파크라인이 뜨는지, 콘솔에 `주식 히스토리 조회 실패` 경고가
안 뜨는지 보면 됨.
