# 투자 결산 탭 — 데이터 구조와 서버 API

## 설계 원칙
- **보유 수량은 서버에 보내지 않는다.** 모든 기록은 브라우저(localStorage, `state.snapshots`)에만 저장되고 백업 JSON에 함께 들어간다.
- 서버는 **가격만** 제공한다 (공개 시세 데이터).
- 스냅샷은 기준일의 `종목별 수량 × 그날 가격 + 그날 환율/S&P500 + 그룹별 입출금`을 통째로 기록한다.
  → 이후 매수/매도해도 과거 기록은 바뀌지 않고, 전량 매도한 종목도 그 달 기록에는 남는다.

```jsonc
state.snapshots["2026-09"] = {
  "month": "2026-09", "date": "2026-09-30",
  "rate": 1356.84,            // 그날 USD/KRW
  "spx": 7651.54,             // 그날 S&P500
  "lines": [                  // g=결산 그룹, t=티커('' 이면 직접입력 줄), q=수량, p=단가, c=통화, e=1이면 추정값(⚠)
    { "g": "성장해외", "t": "NVDA", "n": "엔비디아", "q": 100, "p": 228.38, "c": "USD", "e": 0 }
  ],
  "flows": { "성장해외": 1000000 }   // 월차자금(입+/출−), 그룹별
}
```

## 기록 흐름
1. `📸 스냅샷 기록` → 기준일 선택 (기본 오늘, `지난달 결산일` = 말일/주말이면 직전 금요일)
2. 수량 기준 선택: **지금 보유**(월말 직후 기록할 때) / **직전 기록**(과거 날짜를 늦게 기록할 때). 모두 수정 가능
3. 가격 우선순위: 서버가 그날 저장한 스냅샷 > (오늘이면) 실시간 시세 > `/price_on` 과거 종가 > 직전 기록·현재가(⚠ 추정, 노란 테두리)
4. 수량/가격/입출금을 확인·수정하고 저장

## 서버 API

### GET `/api/snapshots`
서버가 매월 결산일(말일, 토/일이면 직전 금요일) **다음날 06:30 KST**(미국장 마감 후)에 자동 저장한 가격 목록. 놓친 달(12시간 이상 지남)은 저장하지 않는다.
```json
{ "snapshots": { "2026-09": { "date": "2026-09-30", "rate": 1366.62, "spx": 7686.14,
    "prices": { "NVDA": { "price": 200.0, "currency": "USD", "source": "kis_nas" } } } } }
```
사용자가 앱을 안 열었어도 금/은 같은 크롤링 가격이 그날 값으로 남는다.

### GET `/api/price_on?date=YYYY-MM-DD&tickers=NVDA,KRW-BTC,005930`
과거 특정일 종가 조회 (최대 60종목).
```json
{ "date": "2026-09-30", "rate": 1356.84, "spx": 7651.54,
  "prices": { "NVDA": { "price": 228.38, "date": "2026-09-30" } },
  "missing": ["GOLD_비단"] }
```
- 주식: 해당일 이하 가장 최근 종가 (일봉 히스토리 최대 365일, 7일 넘게 오래된 값은 제외)
- 코인: 업비트 일봉 (UTC 날짜 캔들의 종가 = 다음날 09:00 KST)
- 환율 `USDKRW=X`, S&P500 `^GSPC`: Yahoo 일봉
- 금/은 등 크롤링 자산은 과거 데이터가 없어 `missing` → 직접 입력
